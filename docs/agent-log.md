# Agent log

Where the coding agent went wrong, and what caught it. One entry per incident:
what it produced, why it was wrong, and which gate found it (a test, CI, a
review, or a person noticing). The point is the catching mechanism, not the
mistake.

| Date | What the agent did | Why it was wrong | What caught it |
| --- | --- | --- | --- |
| 2026-09-19 | Mounted the pnpm node_modules volumes at apps/api and apps/web before those directories existed in the checkout. | Docker creates a missing bind-mount parent as a root-owned 755 directory, so the dev user could not write into apps/api and the first scaffold command would have failed. | A write test as dev in every mount parent, run while verifying the container instead of on first use. |
| 2026-09-20 | Stored a reverse-charge proposal for an incoming transfer, and built the review list by asking the rules module for every row, so one impossible proposal made the whole review screen return 422. | Reverse charge applies to a purchase, so there is no correct entry for it on money coming in. The rules module was right to refuse; the fault was storing a candidate that cannot become an entry, and letting one bad row hide the other 72. | Running the real bank export through the running API. Both test suites were green: the synthetic fixture had no incoming payment whose nearest neighbour was a reverse-charge purchase. |
| 2026-09-20 | Styled the active navigation tab with the accent colour on top of the default filled button rule, so the selected tab rendered as blue text on a blue background and its label was invisible. | A CSS specificity mistake: `button:not(.link)` outranks `nav button`, so the tab kept the filled background while taking the accent text colour. Nothing failed, and the accessibility tree still read "Review". | Rendering the page in a headless browser and looking at the screenshot. Neither the type checker, the linter nor a DOM query could see it, because every one of them found the text present. |
| 2026-09-20 | Generated synthetic bank texts with a fleet of small models, each batch reviewed by another small model for label fit. The batch for account 1930, company bank transfers, came back containing taxi fares, food deliveries, a salary run and `Bankavgifter`, and its reviewer reported that none of them violated anything. | Those rows belong to five different accounts. Training on them would have taught the model that 1930 is where anything goes, and the same texts appear under their correct labels elsewhere in the set, so it would have been learning a contradiction. | Reading the batches by eye before training, which the design doc requires for exactly this reason. The automated reviewer was the thing that failed, so no automated gate could have caught it. Two batches were dropped and the first round's examples for those labels were kept instead. |
| 2026-09-20 | Planned the trainer around the assumption that `bitsandbytes` would not have a build for the container's CUDA 13.0 torch, and started writing that into the architecture doc as the reason for abandoning 4-bit quantisation. | The assumption was never tested, and it was wrong: `bitsandbytes` 0.50.2 quantises to 4 bits on this card without complaint. A doc correction citing a failure that never happened would have been worse than no correction. | Running the two-line check before writing the claim down. The result changed the code as well as the doc: 4-bit is now an option behind a flag, and the real reason this run does not use it is that a 1.5B model already fits. |
| 2026-09-20 | Planned to serve the fine-tuned model by handing Ollama the merged safetensors directory, on the strength of Ollama importing safetensors for supported architectures. | Ollama 0.34.2 rejects `Qwen2ForCausalLM` from safetensors with `unsupported MLX architecture`. The architecture doc had said all along that the model is served as GGUF; the agent talked itself out of that step because the merge already produced loadable files. | Trying it on the throwaway model from the toy run before the real one had finished training. The blobs upload and only the final create call fails, so the missing piece is the GGUF conversion and nothing else. Serving is the first item in TODO.md rather than a surprise on Monday. |
| 2026-09-20 | Added the Models tab to the frontend by matching the existing navigation markup and inserting a button beside it. The import and the render branch landed; the button did not, so the page existed and was unreachable. | The edit matched the file as it had been written, but Prettier had since re-wrapped that markup across more lines, so the match silently found nothing. The same thing had already swallowed two earlier edits. Nothing failed: the code compiled, the linter was clean, and the tab simply was not there. | Driving the page in a headless browser, where the Models tab could not be clicked. An edit that matches nothing is indistinguishable from an edit that was not needed, so the lesson is to assert the match rather than to trust it, and to check the rendered result rather than the diff. |
| 2026-09-20 | Wrote a doc correction claiming Unsloth's GGUF export was unnecessary because "Ollama imports the merged model directly", hours before discovering that it does not. | The correction was written from the same untested assumption that produced the serving plan. A doc correction is supposed to record evidence, and this one recorded a guess in the voice of evidence, which is worse than the row it replaced. | Re-reading the architecture doc for stale claims after the serving attempt failed. The row now says the GGUF export is needed after all and names Unsloth as the thing to reconsider. Two of the three corrections written today were sound; this one had to be corrected again. |
